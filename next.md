# Issue tracker: Obsidian vault (personal)

Issues and specs for this user live as Markdown notes in the work vault. Root:
`/Users/john.pugliesi/Vaults/spacexai/tickets/` Do not use Linear for this user's tickets. Do not
create GitHub or Origin issues unless the user asks.

## Layout

tickets/ index.md # vault hub (Bases: recent, frontier, blocked, claimed) templates/ticket.md
<project-slug>/ index.md # project hub (Bases for this folder) tkt-<abbrev>-<nnn>.md # one ticket
file

- One file per ticket. Never a combined tickets file.
- A project is a new directory under `tickets/` plus an `index.md` Bases hub.
- Link the project hub as `[[<project-slug>/index]]`.
- Keep closed tickets in the same folder so wiki-links and IDs stay stable.

## Ticket files

Filename is the ID only: `tkt-cm-001.md`. The human title lives in `title` and in the H1. Add the
title as an `aliases` value so `[[Reconnect Change Monitor VFS tools]]` and `[[tkt-cm-001]]` both
resolve.

### Frontmatter

```yaml
---
title: "Reconnect Change Monitor VFS tools"
aliases:
  - Reconnect Change Monitor VFS tools
id: tkt-cm-001
tags:
  - tickets
type: task
category: enhancement
status: needs-triage
priority: 2
project: "[[Change Monitor Agent]]"
parent:
blocked_by: []
claimed_by:
claimed_at:
created: 2026-08-20
updated: 2026-08-20
---
```

Field rules:

- `id` matches the filename stem. Format: `tkt-<abbrev>-<nnn>` with a 3-digit number per project,
  starting at `001`.
- `type` is `task`, `research`, `prototype`, `grilling`, `map`, or `epic`.
- `category` is `bug` or `enhancement`.
- `status` is one triage role from `docs/agents/triage-labels.md`. Closed work uses `wontfix` or a
  trailing `done` value. Prefer `done` when the ticket shipped.
- `priority` is `0` (highest) to `4` (lowest). Default `2`.
- `project` is a wiki-link to the project note when one exists.
- `parent` and `blocked_by` are wiki-links to other tickets, for example `[[tkt-cm-001]]`. Never
  write a bare ID in prose.
- `claimed_by` is the agent or person who holds the ticket. Empty means unclaimed.
- `created` and `updated` use `YYYY-MM-DD`.

### Body

Use this shape (from `/to-issues`) after the H1:

````markdown
# Title

Parent

[[tkt-xx-000]]

What to build

...

Acceptance criteria

◻ ...

Blocked by

• [[tkt-xx-000]]

Comments

Omit **Parent** when there is no parent. Write **Blocked by** as `None - can start immediately` when
the ticket is unblocked. Append comments under `## Comments`. Start each AI triage comment with:

```markdown
> _This was generated by AI during triage._
```
````

## IDs

1. Pick the project folder. Create it and `index.md` if the project is new.
2. List `tkt-<abbrev>-*.md` in that folder.
3. Use the next number. Pad to three digits.
4. Do not reuse an ID. `<abbrev>` is 2–4 letters from the project slug (`change-monitor` → `cm`).

## When a skill says "publish to the issue tracker"

1. Confirm the project folder. Create `tickets/<project-slug>/` and `index.md` if needed.
2. Allocate the next `tkt-<abbrev>-<nnn>` ID.
3. Write `tickets/<project-slug>/<id>.md` from `tickets/templates/ticket.md`.
4. Set `status` to `ready-for-agent` unless the user asked for another role.
5. Link blockers and parents with `[[tkt-…]]` wiki-links in frontmatter and in the body.
6. Do not edit `index.md` by hand. Bases refresh the views.

## When a skill says "fetch the relevant ticket"

Resolve in this order:

1. A `[[wiki-link]]` or `tkt-…` ID → read that file.
2. A title → match `title` or `aliases`.
3. A path under `tickets/`. Then read the whole file, including `## Comments`.

## Wayfinding operations

Used by `/wayfinder`.

- **Map**: a ticket with `type: map` in the project folder. Body holds Notes / Decisions-so-far /
  Fog.
- **Child ticket**: a normal ticket with `parent: "[[tkt-…]]"` pointing at the map.
- **Blocking**: `blocked_by` wiki-links. A ticket is unblocked when every linked ticket has
  `status: done` or `wontfix`.
- **Frontier**: `status` is `ready-for-agent`, `claimed_by` is empty, and every `blocked_by` link is
  done or wontfix. Lowest `priority`, then lowest ID, wins.
- **Claim**: first write. Set `claimed_by` and `claimed_at` (`YYYY-MM-DD`) before any work.
- **Resolve**: append the answer under `## Answer`, set `status: done`, clear `claimed_by`, set
  `updated`, then add a short pointer to the map's Decisions-so-far.

## Bases hubs

`tickets/index.md` shows recent tickets, the frontier, blocked work, and claimed work across all
projects. Each `tickets/<project-slug>/index.md` shows the same views, filtered to that folder. Use
`file.folder == this.file.folder` so the hub does not list nested copies. Exclude `index.md` and
files under `templates/`.

# Triage Labels

The skills speak in terms of five canonical triage roles. This file maps those roles to the `status`
property on each Obsidian ticket.

| Label in mattpocock/skills                                                                                                                  | Label in our tracker | Meaning                                  |
| ------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- | ---------------------------------------- |
| `needs-triage`                                                                                                                              | `needs-triage`       | Maintainer needs to evaluate this issue  |
| `needs-info`                                                                                                                                | `needs-info`         | Waiting on reporter for more information |
| `ready-for-agent`                                                                                                                           | `ready-for-agent`    | Fully specified, ready for an AFK agent  |
| `ready-for-human`                                                                                                                           | `ready-for-human`    | Requires human implementation            |
| `wontfix`                                                                                                                                   | `wontfix`            | Will not be actioned                     |
| Shipped work uses `done` in `status`. That value is extra. It is not a triage role.                                                         |
| When a skill mentions a role (e.g. "apply the AFK-ready triage label"), write the corresponding string into the ticket's `status` property. |

# Domain Docs

How the engineering skills should consume domain documentation when exploring a codebase. This is
personal config. Do not create company `CONTEXT.md` or ADR files from this setup.

## Before exploring, read these

- **`CONTEXT.md`** at the repo root, or
- **`CONTEXT-MAP.md`** at the repo root if it exists — it points at one `CONTEXT.md` per context.
  Read each one relevant to the topic.
- **`docs/adr/`** — read ADRs that touch the area you're about to work in. In multi-context repos,
  also check `src/<context>/docs/adr/` for context-scoped decisions. If any of these files don't
  exist, **proceed silently**. Don't flag their absence. Don't suggest creating them upfront. The
  `/domain-modeling` skill creates them lazily when terms or decisions actually get resolved.

## File structure

This user's default is multi-context:

/ ├── CONTEXT-MAP.md ├── docs/adr/ ← system-wide decisions └── src/ ├── ordering/ │ ├── CONTEXT.md │
└── docs/adr/ ← context-specific decisions └── billing/ ├── CONTEXT.md └── docs/adr/

everysphere does not currently have a root `CONTEXT-MAP.md`. Proceed silently until one exists.

## Use the glossary's vocabulary

When your output names a domain concept (in an issue title, a refactor proposal, a hypothesis, a
test name), use the term as defined in `CONTEXT.md`. Don't drift to synonyms the glossary explicitly
avoids. If the concept you need isn't in the glossary yet, that's a signal — either you're inventing
language the project doesn't use (reconsider) or there's a real gap (note it for
`/domain-modeling`).

## Flag ADR conflicts

If your output contradicts an existing ADR, surface it explicitly rather than silently overriding:

> _Contradicts ADR-0007 (event-sourced orders) — but worth reopening because…_
